# E.X MARKET RADAR Data Contract

## Scope

Phase 2A defines a local Fixture-to-UI contract only. It does not retrieve live data, crawl commercial sites, create accounts, process payments, or claim that the current Market Radar content is live. The current fixture is `public/data/market-radar/2026-08-29.json` and must remain `status: "fixture"` with `isMock: true`.

## Source priority

1. **Tier 1 — Official（官方資料）**: government, public records, property-information platforms, real-price-registration related official data, central bank information, and Kaohsiung City Government public information.
2. **Tier 2 — Institutional / Research（機構／研究資料）**: academic work, formal market reports, and institutional research.
3. **Tier 3 — Editorial / Market Reference（市場參考）**: clearly attributed market media, project information, and industry reports.

Commercial property sites are not crawled by this contract. Any future use must be manually reviewed, lawful, and explicitly attributed.

## Report schema

`MarketRadarReport` keeps the page identity, `status`, `isMock`, page `updatedAt`, public content, pricing, access placeholder, and a single source registry. The static route loads the local fixture through `loadMarketRadarReport()` at build time, rather than importing a hardcoded report object into the route.

## Source schema

`MarketRadarSource` contains `id`, `name`, `publisher`, `type`, `priority`, optional `url`, `publishedAt`, `dataPeriodStart`, `dataPeriodEnd`, `verifiedAt`, `retrievedAt`, `expectedUpdateFrequency`, `notes`, `isPrimarySource`, and `isMock`.

Source IDs are referenced by facts, district highlights, charts, news items, temperature indicators, and the daily key take. The loader rejects unresolved source IDs and resolves valid IDs to source objects for the Detail Drawer.

## Fact and analysis schema

`MarketRadarFact` is the source-backed record: label, value, optional unit/comparison, `sourceIds`, data period, estimation flag, and mock flag.

`MarketRadarAnalysis` is separate from facts: summary, interpretation, impact, impact level, direction, affected audience, confidence, and notes. The UI labels this as **Market Radar 解讀** and explicitly states that it does not represent the original source’s position.

## Chart and content schema

- `MarketRadarChart` supports `line`, `bar`, and `comparison`; it owns axes, series, data period, `sourceIds`, analysis, and Detail Drawer content.
- `districtHighlights` retain district, signals, facts, source IDs, detail, and mock flag.
- `newsItems` retain source IDs, original `publishedAt`, optional editorial `updatedAt`, detail, and mock flag.
- `dailyKeyTake` retains source IDs and `analysisBasis` so a future live observation cannot be ungrounded.

## Time fields

These fields are never interchangeable:

- `report.updatedAt`: Market Radar page update time.
- `source.publishedAt`: original source or report publication time.
- `source.dataPeriodStart` / `source.dataPeriodEnd`: period actually measured by the source.
- `source.verifiedAt`: last Market Radar human or system verification time.
- `source.retrievedAt`: time the system obtained the original source.

## Freshness

`MarketRadarFreshness` records `fresh`, `normal`, `aging`, or `stale`, a readable label, optional days-since counters, and expected update frequency (`daily`, `weekly`, `monthly`, `quarterly`, or `irregular`). A monthly source is not stale merely because it was not published today; a future freshness policy must compare status against its expected cadence.

## Mock versus live

Fixture content is clearly marked `status: "fixture"` and `isMock: true`. A source without a live URL, or any mock source, renders a disabled Mock Source control. Only a non-mock source with a verified `url` may render an external “查看原始來源” link using `target="_blank"` and `rel="noopener noreferrer"`.

## Validation and fallback

`parseMarketRadarFixture()` validates report identity and update time, source registry, source references, district highlights, public charts, and news items. Invalid or incomplete fixtures return `null`; `loadMarketRadarReport()` then renders `marketRadarFallbackReport` so the static page keeps its skeleton and does not white-screen. Development mode warns about the invalid fixture; production falls back quietly.

## Source attribution rules

### SOURCE INTEGRITY RULE

1. Original numeric facts are never generated by an LLM.
2. An LLM must not modify source facts.
3. Every important fact needs at least one `sourceId`.
4. Fact and analysis remain separate fields.
5. Mock content is explicitly marked.
6. Unattributed content must never be promoted to Live.
7. A page update date must never be presented as a source publication date or a data period.

## Phase 2B and future n8n flow

Phase 2B should begin with one official source, preferably an official Ministry of the Interior / real-price related public source. The future flow is:

Official Source → Fetcher or manual import → Normalizer → Market Radar JSON → Schema validation → static data endpoint or R2 → Market Radar UI.

If n8n is introduced later, it may retrieve official data, normalize it, request LLM summaries/classification/analysis, validate the schema, and publish JSON. The LLM may only work from supplied source facts; it must not create or alter original numbers.
